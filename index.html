Historique des activations

🛡️ Ce qui est déjà en place (dans le navigateur)

  • Mots de passe jamais stockés en clair : seule l'empreinte SHA-256 est conservée.
  • Matricule normalisé (espaces retirés, majuscules) et comparaison insensible à la casse, avec unicité imposée.
  • Verrouillage temporaire après 5 tentatives échouées (5 minutes), et déconnexion automatique après 30 minutes d'inactivité.
  • Journal d'audit horodaté (connexions, échecs, créations, suppressions, exports).
  • RBAC par rôle : les formulaires de saisie et boutons de suppression sont masqués pour les profils en lecture seule.
  • Cloisonnement des dossiers d'un « Chef de mission » à son seul département assigné.

⚠️ Limite structurelle à connaître

Cette application est actuellement 100% côté navigateur (aucun serveur, base de données locale). Ces protections réduisent les risques mais restent contournables par une personne qui modifie le JavaScript localement — le frontend ne doit jamais être seul juge des droits d'un utilisateur. Pour un déploiement avec des données réellement sensibles, la vérification des rôles doit être rejouée côté serveur, sur chaque requête.

🏗️ Architecture recommandée pour la version serveur (projet CONNECT)

Frontend : React + TypeScript (Vite ou Next.js)
Backend : Node.js + TypeScript (Express ou NestJS)
Base de données : PostgreSQL + Prisma (ORM)
Authentification : session sécurisée ou JWT court + refresh token
Validation : Zod côté serveur
Exports : PDF (Puppeteer/PDFKit), Word (docx)
Suppression : logique (champ deletedAt), jamais physique par défaut
Renfort : Helmet, limitation de débit, 2FA pour les administrateurs

Rôles cibles : ADMINISTRATEUR (gestion complète), DIRECTEUR et SOUS_DIRECTEUR (lecture globale + export, sans saisie), INSPECTEUR (lecture, audit, export), CHEF_DE_MISSION (saisie et modification limitées à sa mission). Chaque route API doit filtrer les données via une fonction centralisée (buildMissionScope) plutôt que de faire confiance à l'identifiant transmis par le navigateur.

👥 Gestion des Utilisateurs

Inscription des comptes, attribution des rôles et cloisonnement par mission — réservé au profil Administrateur

⚠️ Cette plateforme fonctionne actuellement sans serveur : les comptes et mots de passe (hachés) sont stockés dans le navigateur. Pour un usage réel avec des données sensibles, ces vérifications doivent être rejouées côté serveur (voir l'onglet Sécurité & feuille de route dans Paramètres) — le frontend ne doit jamais être seul juge des droits d'un utilisateur.
